Behavior summary

  • Drag handle (⠿) — grip icon appears on the left, host-only. Initiates drag; avoids conflict with jump-to-ticket clicks.
  • All tickets draggable — done, current, and pending. currentTicketIndex is recalculated server-side after reorder.
  • Optimistic UI — host sees the new order immediately; socket broadcast syncs all participants within ~50ms.
  • No drag for participants — they receive state updates and see the list re-animate into the new order via Framer Motion layout animations.
